# Agent Note: 从官方 observer 读取聊天

Status: implemented

## Problem

各种对话引擎和旁听提取都需要看到实际聊天。模型上下文还包含工具结果和未发送的回复，无法直接作为聊天记录。

## Decision

用户发言及实际发出的机器人回复统一转写为 `[时间] 昵称：正文`。提取和召回用 `chat_observer.recentOfConversation(key, limit)` 读取正文。用户输入按本轮消息 ID 定位；机器人的消息按实际发送事件的轮次、预设和平台 ID 确认归属。旁听沿用同一接口。消费位置仅在插件本次运行内有效，缓冲滚动不改变仍在其中的消息的位置。

共享会话的不同路由共用同一个缓冲，按会话键读取，需要隔离时按每条消息的路由筛选。用户关联取消息本身的平台和发送者 ID；会话当前所在的群或私聊不能代表较早消息的来源。

用户唤醒机器人时，从该条消息往前取最近 `recallHistoryMessages` 条真实聊天（包含该条），按时间顺序固定下来。群聊按群或频道取配置，私聊按对话地址取配置。触发消息决定窗口截止位置。同一份聊天用于判断短期记忆快照是否需要更新，也用于选取当前预设下发言用户已有的非空画像。

快照和画像在本轮首次请求模型时合成一条临时通知。每次请求都将这条通知追加在末尾；工具续步和重试复用同一份内容，通知不写入会话历史。

框架发出的唤醒通知（如定时任务、冷场主动发言）没有对应的用户消息。收到入队事件时直接固定会话缓冲中已有的聊天，等待执行期间的新发言留给后续唤醒。通知只负责触发，既不进入窗口也不推进聊天计数；规则按目标会话匹配，画像仍来自窗口内的发言人。

自动提取按交流分块：普通模式保留完整的问答，旁听模式也处理尚无回复的发言。分块从最新的交流往前取，预算是窗口加半个窗口；普通模式不会为了凑数截断一次交流，旁听长段则优先在机器人回复后切开。

提取开始时固定输入、预设和消费位置。切换预设或重置会话会重新计数；在途调用可以按原预设提交，但不能推进新游标。卸载插件则取消调用并等待任务收尾。重启后重新计数，已经保存的记忆仍可追溯来源。

## Alternatives considered

从 Agent 的模型上下文拼接历史会带入未发送内容，并漏掉旁听。另存回填消息或扩展 Session 都会形成第二个聊天来源。

**单列触发消息或读到批次末尾。** 触发消息已在聊天窗口内，模型无需另收一份。等待引擎合批后再决定截止位置，会把唤醒之后的闲聊提前用于这次召回。

## Consequences

只消费官方缓冲保留的记录；冷启动回填事件没有写入该缓冲的正文不会补入。未进入 observer 的入口也没有可读历史。提取窗口大于可读聊天数时，阈值不会达到。切换历史后的上下文从切换处开始，不能重建分支祖先的聊天。
