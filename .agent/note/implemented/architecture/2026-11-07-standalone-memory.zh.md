# Agent Note: 独立记忆插件与对话规则

Status: implemented

[English](2026-11-07-standalone-memory.md) | 中文

## 问题

LivingMemory 需要独立调度提取、Dream 和画像生成，同时与其他插件共用框架的对话规则和聊天记录。

## 决策

LivingMemory 独立启动、停止、存储和调度。任务页订阅自己的仓储，直接展示 Dream 的部分完成状态。原生插件可以同时启用；两个插件分别处理各自的记忆。

对话行为注册在框架的 `livingmemory` 规则区块。群聊按平台、机器人及群或频道匹配规则，私聊按对话地址匹配。同一地址共用召回、隔离、注入、提取窗口、旁听和后续 Dream 的设置。模型、工具注册和画像生成属于实例配置。规则决定触发和处理方式；群聊正文仍由[官方 observer](2026-11-07-official-observer-window.md)按频道提供。发言人、@ 和消息文本不参与对话地址匹配。

## 考虑过的方案

**保留可选后端。** 原生任务页可以统一查看两种实现，但需要维持两套路由和任务状态映射。独立管理页已能呈现完整的业务状态，继续维护第二个入口没有收益。

**在插件里维护群配置。** 这会再造一套覆盖与继承逻辑，配置也不会出现在框架的对话规则页。

## 影响

自动提取间隔为零的会话不做自动提取。如果只为部分会话开启，可将全局间隔设为零，再按会话覆盖。运行中的回复和已提交给提取器的批次保留触发时的设置；后续触发按新规则处理。规则测试覆盖继承和热更新，仓储与 WebUI 测试覆盖任务通知及部分完成状态。
