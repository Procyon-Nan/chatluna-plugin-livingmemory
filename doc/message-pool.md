# M05：聊天消息来源与消费进度

更新：2026-11-07。决定见 [Agent Note](../.agent/note/implemented/architecture/2026-11-07-official-observer-window.md)。

消息正文来自 `ctx.chat_observer.recentOfConversation(conversationKey, limit)`，与原生 memory 共用入口。接口按频道返回当前缓冲，插件不设置 200 条上限。超出宿主容量的旧消息和只通过冷启动回填事件交给 Agent 的消息读不到；插件不从模型日志补写。

`chatluna/observed` 通知旁听进度。`send` 中的 `chatSent.reply` 提供会话、预设、轮次和平台消息 ID，用于从缓冲中认出真正发出的回复。一次发送返回多个 ID 时只算一次；分段发送分别计数。普通提取等待本轮渲染和回复观察完成，命令通知、工具和思考不计入阈值。

消费按聊天条数计算。插件只为缓冲对象标记位置和回复归属，不保存第二份聊天正文。遇到工具或通知直接跳过，保留原有的 `[时间] 昵称：正文` 转写。纯旁听达到阈值可以提取；关闭旁听时仍按完整交流分块。

用户唤醒机器人时，从触发消息往前读取最近 N 条聊天（含触发消息），N 为「召回上下文条数」。例如 Alice @ 机器人后 Bob 又发了言，本轮使用当前群或频道的设置，聊天截止在 Alice 那一条。Bob 后发的消息即使同批投递，也留待下次触发时作为历史。画像注入使用同一窗口，按发言人去重，不受自动召回间隔限制。

定时任务或冷场通知唤醒机器人时，以通知进入 Agent 队列时的频道缓冲末尾为截止点。通知正文不进入聊天窗口，也不增加聊天计数。没有新聊天时连续唤醒不会重复调用召回模型。通知与同一群、频道或私聊里的用户消息使用相同的对话规则。

重启和每次预设切换都重新计算提取阈值；切回同名预设也重新开始。同一历史更换模型、重建 Agent 不清除进度。重置、切换或分支会话时，仅使用新边界之后的频道消息。已经开始的批次按原作用域结算，失败重试保留同一批正文，卸载时取消。已保存的记忆、画像和来源导入不受影响。

会话记录未写入预设时，本轮仍按 Agent 已确定的预设召回和注入。旁听沿用同一会话已确认的预设；尚未确认时，从该会话的活跃 Agent 或会话记录确定归属。三者都没有预设时，该条旁听消息不计入提取阈值。

## v1 现状

| 项目 | 当前实现 |
| --- | --- |
| 所有者 | `ChatLunaLivingMemoryService` 持有 `MessageLogRegistry`；注册表按 `conversationId` 管理日志 |
| 存储 | 内存滚动日志，每会话容量 500 条；日志、去重键和提取游标随进程生命周期存在 |
| 普通对话 | `before-chat` 写入用户请求，`after-chat` 补入用户与回复文本；注册时提供会话绑定，使用实时输入建立消息池 |
| Character | 平台采集器持续记录符合接收范围的用户消息；`after-chat` 补入实际发出的回复；注册时额外提供 bot，用于平台历史回填 |
| 历史预热 | Character 冷启动回填目标为 200 条；适配器提供的分页决定实际取得的数量；缺少历史能力时从实时消息开始 |
| 顺序与去重 | 入池分配单调递增 `seq`；优先按消息 ID 去重，缺少 ID 时按用户、时间、内容组合去重；淘汰条目时同时移除对应去重键 |
| 回填与实时并发 | 回填期间实时消息进入临时缓冲；回填完成后先写历史，再写缓冲；重复项保留实时版本 |
| 回填失败 | 保留缓冲与未就绪状态，下次预热重试 |
| 召回读取 | 定位当前触发消息，读取它之前的历史窗口；定位失败时当前实现读取最近窗口 |
| 提取读取 | 每个预设与会话维护自己的游标；普通对话按完整交流片段取块，开启旁听提取时可以消费旁听消息 |
| 提取结果 | 单块处理正常返回后推进游标；抛出异常时保留游标，连续 3 次异常后记录失败任务并跳过该块；跳过及解析失败等正常返回分支的迁移语义在 M06 细化 |
| 清理 | 清空日志推进时间纪元并保留序号计数；释放注册表清除内存池；记忆的来源文本另行保存在记忆数据中 |

500 条约束针对单个已落池日志。当前注册表的会话数量、回填临时缓冲和未消费消息保留量由上述逻辑决定；持续积压时，容量淘汰会移除尚未提取的旧消息。普通对话与 Character 的历史预热能力取决于各自接入提供的历史来源。v2 迁移将这两类采集接入统一到公共消息入口。
