# Agent Note: LivingMemory 自动提取窗口与分块

Status: proposed

## Problem

LivingMemory v1 的自动提取把消息阈值、交流边界、旁听消息和模型输入分块连接在同一条消费链上。ChatLuna v2 原生流程目前按会话读取 observer 的最近窗口并直接调用后端；如果迁移时把最近窗口当成完整实现，会改变完整交流、旁听和消费游标的行为。

## Proposal

LivingMemory v2 继续由自身维护自动提取消费起点、批次上界和分块规则。ChatLuna v2 负责提供统一归属的消息输入，后端适配将消息窗口交给 LivingMemory 的自动协调器处理。

沿用 v1 的分块语义，具体规则如下：

1. `extractionWindowMessages` 继续表达自动提取的累计阈值，并作为分块的窗口参数；v2 新安装默认值留到 M08 统一确定。
2. 普通完整交流模式按连续 assistant 段闭合交流。保留最新闭合交流及其前方窗口范围内的上下文；窗口边界切入一段交流时保留该交流的完整内容；核心范围之外的闲聊随本批消费边界推进，不再进入后续提取。
3. 旁听模式在上述分段基础上保留末尾尚未得到 assistant 回复的用户段，使未触发回复的消息也能进入提取；超出预算的长段按 assistant 边界切成多个子块。
4. 分块吸收预算为 `window + floor(window / 2)`。从最新单元向较旧单元装包，优先保持最新内容及其上下文；完整交流单元作为原子单元，超过预算时不在普通模式中截断，旁听长段使用专门切片规则。
5. 阈值判断、分块规划和模型执行分开处理。任务启动时固定本批消息范围，执行期间的新消息进入后续累计；正常完成只推进到本批边界，遵循 M06-D2 的结果状态和失败处理。
6. 每个自动消费作用域继续使用自己的内存游标。预设切换和重启按 M06-D1 建立新起点，旧计数与待提取积压不接续。

这组规则只定义自动提取的窗口与分块，不确定配置默认值、取消时的在途模型调用处理，也不改变统一消息池的采集职责。

## Alternatives considered

**直接使用 v2 observer 最近窗口**：实现简单，但无法表达 v1 的完整交流边界、旁听末尾用户段和本批消费游标，因此会改变迁移后的自动提取范围。

**按固定 N 条消息硬截断**：可以得到稳定的消息数，但可能把用户请求与 assistant 回复拆开，也无法保留超出边界的完整交流单元。

**迁移时重写分块算法**：可以重新设计上下文取舍和预算，但会同时改变 v1 的行为与迁移验证范围。当前没有足够依据证明需要在迁移阶段承担这项变化。

## Acceptance criteria

- 普通模式在窗口边界切入交流时保留完整交流，较旧闲聊随消费边界推进。
- 旁听模式能够消费末尾纯用户段；超长段切片时优先在 assistant 消息后切分。
- 分块按最新内容优先装包，吸收预算符合窗口加半窗口的规则；完整交流单元不被普通模式截断。
- 执行期间新消息不进入已固定批次；成功、有效空结果、失败重试和跳过均按 M06-D2 推进。
- 预设切换、切回和重启重新建立计数起点，旧游标和积压不会影响新一轮阈值。
- `agent`、`coding`、`character` 等引擎使用同一消息池、游标和分块实现，差异只出现在触发、消费时机和记忆注入边界。

## Risks

- 同一配置同时参与触发阈值和分块预算，后续调整其中一项时需要同步评估另一项的行为。
- 完整交流单元可以超过吸收预算，单次模型输入可能大于窗口数值；需要在 M04 的模型预算验证中测量，而不是在迁移方案中静默截断。
- 内存消息池容量淘汰可能先于自动提取处理未消费的旧消息；容量和淘汰策略由 M05、M08 分别确认。
